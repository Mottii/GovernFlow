# Implementation decisions

- T1.1: `uv` pins Python dependencies. FastAPI and uvicorn serve the native HTTP endpoints; httpx handles asynchronous upstream forwarding; SQLAlchemy, asyncpg, and Alembic manage Postgres; pydantic-settings validates environment configuration; cryptography provides AES-GCM. pytest, pytest-asyncio, and respx test async calls; ruff and mypy run in CI. Each dependency is required by the blueprint's fixed stack.
- T1.1: The administrative API uses a separate ASGI app and port so proxy credentials cannot access its routes.
- T1.2: Migration 0001 follows section 18.4. The PDF's approvals status check is truncated, so the migration completes it with `expired`, which section 18.6 requires. `pgcrypto` supplies `gen_random_uuid()` on older local Postgres; Postgres 16 also accepts it.
- T1.3: Provider keys use AES-GCM with client, provider, and label as associated data. Virtual keys are random `gk_` strings stored only as SHA-256 hashes and shown once at creation. The phase-1 admin API requires `ADMIN_TOKEN` and runs on its own port.
- T1.4: Authentication resolves the client and workflow with one scoped query and rejects revoked keys or inactive tenants. The public proxy uses provider-shaped errors rather than FastAPI's default `detail` wrapper.
- T1.5: The OpenAI Chat adapter forwards request bytes and returns provider response bytes unchanged. It reads usage from a copy of the response and keeps cached and reasoning tokens separate to avoid double counting in later cost accounting.
- T1.6: Migration 0002 adds per-run reservations and a reservation ledger. Monthly and run reservations occur in one database transaction; settlement and release lock the ledger row, so retries cannot apply them twice. Missing prices fail closed. Policy uses integer `per_run_micro`, replacing the PDF's floating `per_run_usd` in storage.
- T1.7: Each client has a serialized SHA-256 event chain over canonical JSON. Provider-call events commit in the same transaction as budget settlement or release; an independent CLI verifies the entire chain.
- T1.8: Kill flags are checked global, client, then workflow before request policy and budget work. Per-replica cache entries expire in at most five seconds, matching the blueprint's propagation target.
- T1.9: For OpenAI streams, the gateway requests the terminal usage frame when the caller did not. It parses complete SSE frames and removes that injected usage-only frame before returning data; this adds at most one frame of buffering, a necessary exception to the blueprint's literal unbuffered wording. A missing terminal usage frame settles the reservation as estimated.
- T1.10: `/v1/models` returns the priced OpenAI models visible to the authenticated workflow in the standard model-list shape, which supports n8n's credential probe without calling a provider.
- T1.10: Compose publishes Postgres on host port 55433 by default because port 5432 is occupied on the development host. Containers still use port 5432; `POSTGRES_HOST_PORT` overrides the host port.
- Phase 1 hardening: The n8n OpenAI node revealed a lock-order deadlock under overlapping reserve and settle operations. Both now update the budget before the run. A separate Compose maintenance service releases reservations older than one hour once daily and records a `reservation_reaped` audit event; this implements section 18.5 crash recovery.
- T2.1: Anthropic Messages uses a native `/v1/messages` route, `x-api-key` virtual-key authentication, unmodified request and response bytes, and unmodified SSE chunks. The parser reads a copy of `message_start` and cumulative `message_delta` usage and requires `message_stop` before using measured cost; interrupted streams settle as estimates. Anthropic's `input_tokens` excludes its separately reported cache tokens. Caller-supplied workspace headers are not forwarded; phase 4 will select the mapped client workspace.
- T2.2: OpenAI Responses and embeddings preserve native bodies. Responses usage excludes cache read/write and reasoning tokens from base counts; final completed or incomplete events carry usage. Embeddings reserve input cost only. The official OpenAI Python SDK passed normal and streamed Responses and embeddings against the mock provider. All 17 tests, ruff, and mypy passed.
- Live credentials: The user confirmed on 2026-10-06 that Telegram and provider reporting credentials are not currently available. Implementation and mock protocol acceptance continue; live checks must remain explicitly pending.
- T2.3: Gemini uses native `/v1beta/models/{model}:generateContent` and `streamGenerateContent` routes, with virtual keys in `x-goog-api-key` or the native `key` query parameter. Upstream authentication replaces that key; native query options and bytes are preserved. The plain HTTP contract covers both `alt=sse` and JSON-array streams. Cache and thoughts are accounted separately using Google's documented usage metadata. A shared byte relay parses a copy and estimates interrupted streams.
- T2.4: Gateway failures use OpenAI, Anthropic, or Gemini error envelopes selected by the native route. `x-gateway-error` carries a stable governance code without altering provider envelopes. Database failures return a sanitized 503 and fail closed; upstream errors retain bytes, status, and retry headers. Error shapes were checked against https://platform.claude.com/docs/en/api/errors and https://ai.google.dev/gemini-api/docs/troubleshooting.
- T2.5: Migration 0003 adds workflow/minute rate buckets. Atomic Postgres upserts share RPM limits across replicas and provider dialects. A denied call returns 429 with `Retry-After`; models outside the configured allowlist return native 403. An absent allowlist permits no model.
- T2.6: Migration 0004 adds durable alerts. Atomic run updates enforce step and run-cost limits; shared counters enforce the configured loop RPM. A loop breach sets the workflow kill flag, writes an alert, and appends an audit event. Actual charges above reservations are recorded in full and atomically stop subsequent calls with a `budget_overrun` alert and event. Pre-call estimates do not guarantee a final provider charge stays below a cap.
- T2.7: All native calls now share one reservation and streaming relay. Recorded fixtures come from the deterministic mock, with official schema references in `tests/fixtures/manifest.json`; they are not live provider captures. CI exercises official OpenAI and Anthropic SDKs, Gemini HTTP, native tools and long output, tenant credentials, timeouts, and missing or interrupted usage.
- T2.7 outage policy: Only an administrator-configured `outage.mode=open` on R0/R1 can populate a replica's 60-second memory cache after a governed call reserves successfully. Unknown, expired, and R2/R3 snapshots fail closed. The durable SQLite queue stores accounting metadata only, uses full disk sync before forwarding, and replays with migration 0005 idempotency receipts. Outage calls carry `x-gateway-estimated: true`. Replica allowances bound cached remaining budget and call count, but cannot coordinate global budgets or newly changed kill flags while Postgres is unavailable. This limitation is inherent in the explicitly enabled fail-open mode. A crash before a provider response replays the estimate after one hour. Settlement failures queue accounting without repeating provider calls.
- T3.1: `/v1/actions/check` and scoped poll routes run on the gateway. Human decision routes run on the separate admin API. Strict unknown-action denial is the default; effective risk cannot be lower than workflow risk. Migration 0006 adds encrypted action content and a timeout outcome for review and expiry. Action content uses AES-GCM and the audit retains only approval references or hashes.
- T3.2: Migration 0007 adds a durable notification outbox. Telegram callbacks bind the approval, decision, and private approver chat using a 128-bit HMAC within Telegram's 64-byte callback limit. The separate admin webhook verifies Telegram's secret header and sender. Signed review links show escaped full action content and require a POST to decide; one row lock prevents repeated decisions. The setup helper reads secrets from `.env` without printing them. Live delivery is pending user credentials.
- T3.3: SMTP sends plain text and escaped HTML with signed review links; STARTTLS is the default. Webhook notifications and incoming decisions use a separate `WEBHOOK_SIGNING_KEY`, timestamped HMAC over the raw body, a five-minute freshness window, and migration 0008 replay receipts. This integration secret is distinct from the gateway's decision-token signing key.
- T3.4 — correction to PDF sections 18.3/18.6: SDKs do **not** verify HMAC locally and never receive the signing secret. They submit the opaque token and exact action to `/v1/actions/consume`. The gateway verifies purpose, workflow, action hash, expiry, status, and single use under an approval row lock. Migration 0009 stores consumption time. Execution tokens expire at the earlier of the approval deadline and 15 minutes after the decision; polling cannot extend validity.
- T3.5: The expiry worker and polling transition pending rows to `expired` once, under row locks, and record the configured outcome. Timeout denial is the default and mandatory for R2/R3. An administrator may require review of a low-risk action and explicitly allow it on timeout; that expired record receives a fresh, bounded execution token and remains auditable as expired. No SDK decides expiry locally.
- T3.6: Proposed, approved, denied, expired, and consumed action transitions enter the same client audit chain in the transaction changing their status. Decision metadata includes the approver, workflow, and action hash; encrypted action content remains separate. The chain verifier detects altered decision metadata.
- T4.1: Migration 0010 adds price provenance, billing metadata, and one-hour cache-write rates. The seed contains six supported starter models checked against official pricing on 2026-10-06. GPT-6 long-context multipliers and Anthropic cache TTL rates use integer fractions. Standard token entries reject billing options without a configured meter; native function tools remain supported. Sources and scope are in `docs/prices.md`.
- T4.2: Migration 0011 adds dedicated provider-account mapping, daily usage/cost snapshots, and job outcomes. OpenAI usage is compared by project and model; costs retain the supported project/line-item grouping. Anthropic usage is compared by workspace and model; costs retain workspace/description groups and are filtered locally because the cost endpoint has no workspace filter. Anthropic cost amounts are cents, converted with Decimal to integer micro-USD. Gemini remains gateway-observed. Live forwarding requires validated account mapping; OpenAI receives the mapped project header, while Anthropic uses a key validated as belonging to its workspace. Failed reporting jobs never substitute zero for unknown usage or costs.
